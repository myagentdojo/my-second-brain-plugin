# New Skill Formation Context

This context names the language used to form one resumable skill across the
supported Harnesses. It separates a truthful scaffold, human decisions, and
verification claims.

## Language

**Formation Run**:
One bounded passage from a skill idea or Formation Packet to an approved
implementation frontier.
_Avoid_: implementation run, autonomous build

**Formation Packet**:
The vault-owned project record that preserves the skill outcome, decisions,
evidence, owners, and next frontier across turns.
_Avoid_: workflow ledger, scratch log

**Formation Preview**:
The exact pre-mutation description of the selected plugin, packet,
branch/worktree, payload paths, repository-pattern test, effects, and
exclusions.
_Avoid_: rough plan, implicit consent

**Domain Naming Pass**:
The read-only pre-preview decision that binds every proposed domain-bearing
stub name to the governing glossary and settles missing or overloaded terms.
_Avoid_: placeholder naming, architecture design

**Bare Skill Shell**:
The selected skill directory plus its minimal valid `SKILL.md`, created as the
writable landing zone before any distinct skill-local term is resolved.
_Avoid_: empty glossary, Mandatory Skill Scaffold

**Mandatory Skill Scaffold**:
The post-grill source shape containing the accepted skill, its source guidance,
and its discovery contract, plus a mapped skill-local glossary only when
distinct skill-local domain vocabulary resolved. Coding standards are derived later from
settled architecture and test evidence.
_Avoid_: finished skill, accepted design

**Complexity Gate**:
The decision boundary that keeps a skill payload-only unless its state,
filesystem, external, process, recovery, module, or seam needs justify a
package shell.
_Avoid_: effort estimate, model selection

**Architecture Shell**:
The human-reviewed map of modules, interfaces, seams, paths, and stubs that
precedes package-shell creation when the Complexity Gate fires.
_Avoid_: implementation, final architecture

**Domain Structure Map**:
The Architecture Shell table pairing each domain-bearing folder, file, type,
interface, and test title with its exact accepted glossary term.
_Avoid_: generic folder convention, technical-layer map

**Shared-understanding confirmation**:
The user's explicit confirmation that the grill's outcome and domain language
match the intended skill.
_Avoid_: inferred agreement, Formation approval

**Repository-pattern test**:
A discovery-only repository test that checks a source contract at the
repository seam without claiming native host behaviour.
_Avoid_: runtime test, activation proof

**Coding Standards Preview**:
The exact late-stage proposal for the selected skill's standards path,
repository-wide pointer, evidence-backed package idioms, exclusions, and file
effects after architecture and Test Design are settled.
_Avoid_: empty standards stub, copied global rules

**Scaffolded**:
Artifact maturity meaning valid shape exists without behaviour proof.
_Avoid_: accepted, verified

**Accepted**:
Artifact maturity meaning a human has settled the relevant decision, spec,
ADR, architecture, or checkpoint.
_Avoid_: scaffolded, merely reviewed

**Verified**:
Artifact maturity meaning a named check passed for a specific claim at its
seam.
_Avoid_: globally proven, native-qualified

**Implementation frontier**:
The packet-linked boundary containing the approved spec and ticket graph where
later implementation may begin.
_Avoid_: implementation complete, release candidate
